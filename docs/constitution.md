# Constitución: Gestor de Finanzas Personales

Principios arquitectónicos, financieros, de seguridad y de calidad de ingeniería innegociables del sistema.

1. **Entorno de Ejecución Local**: FastAPI, SQLite local, Streamlit y Docker; integración con LLM en la nube permitida exclusivamente mediante la API de Google Gemini utilizando la clave personal del usuario.
2. **Lógica Desacoplada y Fuente Única de Verdad (SSOT)**: Los algoritmos financieros y presupuestarios (50/30/20, desviaciones, fondos de seguridad, indicadores y cálculos de mercado) y las herramientas de agentes deben residir desacoplados como servicios o funciones puras testeables bajo `src/backend/services/`. La interfaz de Streamlit (`src/frontend/`) es exclusivamente una capa de presentación visual; queda prohibida la duplicación de cálculos financieros en el frontend.
3. **Arquitectura Limpia y Principios SOLID**: Código estructurado bajo principios SOLID: responsabilidad única por módulo, inversión de dependencias mediante interfaces explícitas (`db_interface.py`), segregación de repositorios y sustitución limpia de componentes.
4. **Simplicidad Pragmática (KISS y YAGNI)**: Priorizar la simplicidad frente a la complejidad innecesaria. Queda prohibido introducir abstracciones prematuras o componentes no requeridos por la especificación activa.
5. **Seguridad de Tipado y Validación Defensiva**: Uso riguroso de modelos fuertemente tipados con SQLAlchemy 2.0 y validación de esquemas con Pydantic v2 en todas las fronteras de datos, garantizando precisión numérica y redondeos controlados.
6. **Degradación Elegante y Resiliencia**: Las caídas o límites de cuota de APIs externas (Yahoo Finance, BCE, Gemini) deben gestionarse de manera resiliente mediante cachés o valores de respaldo, impidiendo que la aplicación se rompa.
7. **Veracidad Cuantitativa**: Queda terminantemente prohibido simular, alucinar, inventar o falsear métricas financieras en código de producción.
8. **Guardia de Seguridad del Fondo de Emergencia**: Regla innegociable: jamás sugerir, asignar o permitir inversiones con riesgo si el fondo de emergencia no cubre al menos 3 meses de gastos fijos esenciales.
9. **Privacidad Local y Protección de Datos**: Los registros contables y transacciones financieras personales residen exclusivamente en local; a la API de Gemini solo se enviarán datos macroeconómicos públicos, noticias o resúmenes disociados autorizados. Queda prohibido exponer, imprimir o registrar datos sensibles (claves API, tokens o credenciales).
10. **Observabilidad Obligatoria y Prohibición de Fallos Silenciosos (`Silent Failures`)**: Queda terminantemente prohibido silenciar excepciones mediante `pass` ciego o capturas vacías. Toda llamada de red (ej. `src/frontend/api_client.py`), integración con APIs externas, acceso a datos, servicios y controladores debe instrumentarse con el módulo estándar `logging` (`logger.warning`, `logger.error`), registrando la URL invocada, el código de estado HTTP y el detalle del fallo sin comprometer la resiliencia de la UI ni la privacidad.
11. **Declaración Explícita y Paridad de Dependencias (`requirements/`)**: Regla innegociable de cero dependencias implícitas: toda librería externa utilizada en `src/backend/` o `src/frontend/` (o instalada en `venv`) debe registrarse de forma inmediata y explícita en su manifiesto correspondiente (`requirements/backend.txt` o `requirements/frontend.txt`). Queda terminantemente prohibido confiar en dependencias transitivas del entorno local `venv` (ej. `streamlit` instalando `python-multipart`), debiendo auditar activamente antes de cualquier fusión de rama que `docker compose up --build` y el actualizador OTA sean 100% reproducibles sin paquetes faltantes.
12. **Política de Idioma y Nomenclatura (Estándar Internacional)**:
    - **Código Backend, Base de Datos y API (100% en Inglés)**: Tablas, columnas, modelos SQLAlchemy, esquemas Pydantic, routers, endpoints, métodos, funciones y variables deben redactarse en inglés (ej. `Category`, `Transaction`, `MonthlyBudget`, `EmergencyFund`, `MarketCache`, `amount`, `current_balance`, `/categories`, `/advisor/safety-status`).
    - **Interfaz de Usuario, Documentación y Explicaciones (100% en Español)**: Interfaz gráfica de Streamlit, documentos en `specs/`, `README.md`, guías, docstrings explicativos y comunicación en el chat deben estar en español.
13. **Formato Estándar de Fechas (`DD/MM/AAAA` vs ISO 8601)**:
    - **Presentación y Exportación (100% en `DD/MM/AAAA`)**: En toda la interfaz de Streamlit, tablas visibles, selectores de fecha (`st.date_input(..., format="DD/MM/YYYY")`), tooltips, descargas de reportes CSV/Excel y registros para el usuario, las fechas deben mostrarse estrictamente en formato español **`DD/MM/AAAA`** (o `DD/MM/AAAA HH:MM:SS` con hora). Queda prohibido mostrar fechas como `AAAA-MM-DD` o `AAAA/MM/DD`.
    - **Almacenamiento y Contratos API (`ISO 8601`)**: Internamente en la base de datos SQLite y en contratos REST de FastAPI se mantiene el estándar técnico ISO 8601 (`YYYY-MM-DD` o ISO UTC) para garantizar ordenamiento e interoperabilidad.
